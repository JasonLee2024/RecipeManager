## 一、下厨跟做者



1. **菜谱在哪**  

   所有可读菜谱正文在仓库 **`Docs/菜谱/`** 下，按 **`主食`、`炒菜`、`凉菜`、`汤羹`、`蒸菜`、`烤菜`** 等文件夹分类，文件扩展名为 **`.md`**（Markdown）。



2. **怎么找**  

   - 在资源管理器或编辑器里展开 `Docs/菜谱/<分类>/`，按菜名打开对应文件即可。  

   - 许多文档开头有「推荐分类 / 推荐标签」，便于理解归类；做法以正文「食材」「做法」「小贴士」为准。



3. **需要装模块吗**  

   **不需要。** 只跟做、不用终端检索、也不改菜谱数据时，当作普通 Markdown 阅读即可。



4. **想多学一点方法**  

   跨菜谱的技巧、流程可参考 **`Docs/最佳实践/`**（入口：`Docs/最佳实践/最佳实践索引.md`）。

## 二、终端检索用户



### 环境与加载模块



- 本模块面向 **PowerShell 7+**（见 `RecipeManager.psd1` 中的 `PowerShellVersion`）。

- 若模块目录已在 `$env:PSModulePath` 中（例如放在 `文档\PowerShell\Modules\RecipeManager`），在模块根目录的上一级执行：

  ```powershell

  Import-Module RecipeManager -Force

  ```

- 若尚未加入路径，可先 **`cd` 到本仓库（模块）根目录**，再加载清单：

  ```powershell

  Set-Location <RecipeManager 仓库根目录>

  Import-Module .\RecipeManager.psd1 -Force

  ```



### 常用命令（检索与界面）



| 目的 | 命令示例 |

|------|----------|

| 列出全部菜谱 | `Get-Recipe` |

| 按分类 | `Get-Recipe -Category '凉菜'` |

| 按标签 | `Get-Recipe -Tag '快手菜'` |

| 按名称模糊 | `Get-Recipe -Name '茄子'` |

| 按正则精确匹配名称 | `Get-Recipe -Name '^番茄炒蛋$' -Regex` |

| 交互检索（Out-GridView 等，依环境而定） | `Invoke-RecipeUI` |

| 持久控制台循环（选菜后进行删除等流程） | `Start-RecipeManager` |



更完整的参数与示例见各命令帮助：



```powershell

Get-Help Get-Recipe -Full

Get-Help Invoke-RecipeUI -Full

Get-Help Sync-RecipeDocs -Full

```



### 其他对外命令一览



模块导出函数见 **`RecipeManager.psd1`** 的 **`FunctionsToExport`**，主要包括：菜谱 CRUD（`Get-Recipe`、`New-Recipe`、`Set-Recipe`、`Remove-Recipe`）、存储迁移（`Migrate-RecipeStorage`）、文档同步（`Sync-RecipeDocs`）、标签补齐（`Update-RecipeIngredientTags`）、工作流与药膳与饮料查询（`Get-CookingWorkflow`、`Get-HerbalMaterial`、`Test-HerbalMaterial`、`Get-BeverageTaxonomy`）等。详细用法以 **`Get-Help <命令名> -Full`** 为准。

## 三、菜谱维护人员



### 1. 数据与文档各放哪里



- **人类可读菜谱正文**：`Docs/菜谱/<分类>/…/*.md`  

- **结构化菜谱数据（检索/UI/校验用）**：`Data/Recipes/<分类>/<菜名>.json`（分片存储，一条菜谱一个文件）。  

- **文档路径索引（分类 ↔ 文档路径）**：`Docs/CategoryDocIndex.json`（可由命令重建，见下文）。



约定摘要见 **`Docs/配置说明/00_总览.md`**。



### 2. 新增或调整菜谱时的推荐流程



1. **编辑或新增** `Docs/菜谱/…` 下的 `.md`。  

2. **同步 JSON 与索引**：在模块已加载的前提下执行：

   ```powershell

   Sync-RecipeDocs

   ```

   会为**缺失**的文档生成最小 JSON 骨架，并**重建** `Docs/CategoryDocIndex.json`；已存在的 JSON 会按需补齐 `DocPath`、`DocCategories`、`Category` 及文档中可识别的地域标签等（详见 `Get-Help Sync-RecipeDocs -Full`）。  

3. **补全食材类 Tags（可选）**：根据 `Ingredients.Item` 推断 `食材/...` 路径标签：

   ```powershell

   Update-RecipeIngredientTags -WhatIf   # 先预演

   Update-RecipeIngredientTags -Confirm:$false

   ```

4. **手工编辑 JSON**：补全 `Ingredients`、`Steps`、`PrepTime`、`Tags` 等；保存后若开启严格校验，非法分类或标签会导致校验失败（见 `Config/Settings.json` 中的 `Policy.StrictValidation`）。



### 3. 配置与标签合规



- **一级分类**（如 `炒菜`、`凉菜`）须在 **`Config/RecipeTaxonomy.json`** 的 **`Categories`** 中。  

- **`Tags`** 合法池来自 taxonomy 主标签、`口味/…`、`场景/…`、`厨具/…`、**`Config/IngredientTaxonomy.json`** 展开的 **`食材/…`** 路径，以及 **`Config/RegionalCuisines.json`** 中的地域条目等（校验逻辑见模块内策略说明文档 **`Docs/配置说明/06_Enums_分类与标签体系.md`**）。  

- **地域标签**：仅在文档或数据中有可靠依据时使用 `RegionalCuisines.json` 中的名称；勿臆造。



### 4. 与 Cursor / 协作规则



若在 Cursor 中打开本仓库，**`.cursor/rules`** 中的约定（例如：`Docs/菜谱` 变更须与 `Data/Recipes` 同步、`DocPath` 使用仓库相对路径等）会在协作时提示；提交前建议执行 **`Sync-RecipeDocs`** 并跑 **`Tests/RecipeManager.Tests.ps1`**（或团队约定的 CI），避免索引与校验不一致。



### 5. 延伸阅读（菜谱维护人员）



| 主题 | 文档 |

|------|------|

| 配置总览 | `Docs/配置说明/00_总览.md` |

| 分类与标签 | `Docs/配置说明/06_Enums_分类与标签体系.md`、`Docs/配置说明/06a_Enums_维护与扩展速查.md` |

| 地域菜系 | `Docs/配置说明/05_RegionalCuisines_地域菜系.md` |

| 食材多级标签 | `Config/IngredientTaxonomy.json`（说明见配置说明索引） |

| 变更记录 | `CHANGELOG.md` |

## 小结



- **下厨跟做者**：读 `Docs/菜谱/**/*.md` 即可。  

- **终端检索用户**：`Import-Module` → `Get-Recipe` / `Invoke-RecipeUI`，详情 `Get-Help`。  

- **菜谱维护人员**：`.md` + `Data/Recipes/*.json` + `Sync-RecipeDocs`；标签与分类对齐 **`RecipeTaxonomy`**、**`IngredientTaxonomy`**、**`RegionalCuisines`**。
