# Noodles 维护与扩展速查

对应配置文件：`Config/Noodles.json`

本文是 `03_Noodles_面食条目库.md` 的操作补充，聚焦“日常维护怎么做”。

---

## 1. 适用场景

- 新增面食名称（如新增地区小吃）
- 调整分组（如把条目从“通用拌面体系”迁入更细风味组）
- 排查 `NoodleStyle` 校验失败

---

## 2. 结构约定（当前版本）

`Config/Noodles.json` 采用对象结构：

- 顶层：`NoodleDishes`
- 二级键：风味分组（如 `港粤风味`、`江浙沪风味`）
- 值：字符串数组（菜名）

约定：

- 同一条目只保留一份，避免跨组重复导致维护成本升高
- 菜名尽量使用“成品名”而不是“做法名”或“品牌名”
- 分组名称保持稳定，避免频繁改名影响历史数据理解

---

## 3. 新增条目的标准流程（SOP）

1. 选择目标分组（若暂无合适分组，先评估是否真的需要新建分组）
2. 检查全文件是否已存在同名条目（避免重复）
3. 按分组语义插入条目
4. 保存后执行模块测试，重点关注 `NoodleStyle` 相关用例
5. 若涉及语义变更，在 `Docs/配置说明/03_Noodles_面食条目库.md` 补充说明

---

## 4. 常见问题排查

### Q1：`NoodleStyle` 校验失败

检查顺序：

1. 菜谱里的 `NoodleStyle` 字符串与 `Noodles.json` 是否完全一致（含全角/半角）
2. 条目是否写在了错误分组下但实际没有入库
3. 是否存在同义写法（如“红烧牛肉面” vs “红烧牛肉麵”），需要统一一个标准写法

### Q2：一个条目是否允许出现在多个分组？

当前建议：**不建议**。优先单一归属，降低检索和维护歧义。  
如果确有跨域需求，建议后续升级为对象结构（含主分组与标签），不要直接复制多份字符串。

---

## 5. 扩展建议（未来版本）

如需更精细检索，可从字符串数组升级为对象数组，例如：

```json
{
  "Name": "阳春面",
  "PrimaryRegion": "江浙沪风味",
  "Aliases": ["光面"],
  "Notes": "上海/苏州常见"
}
```

升级前建议先确认：

- 校验逻辑是否同步改造（`Invoke-RecipeValidation`）
- 历史 `NoodleStyle` 数据是否需要迁移
- 文档与测试是否一并更新
