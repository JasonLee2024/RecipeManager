# HerbalMedicineSchema（药膳药材知识框架）说明

对应配置文件：`Config/HerbalMedicineSchema.json`

## 定位

该文件用于构建中医药膳场景下的药材知识框架，覆盖：

- 基础属性（来源、部位、道地、采收炮制）
- 中医药性（四气五味、归经、升降浮沉、毒性、用量用法）
- 功效主治（功效分类、主治、现代适应症、经典方剂）
- 药膳应用（配伍、体质、时令、禁忌）
- 现代研究（成分、药理、质量标准）
- 古籍溯源（首载、历代论述、名家经验）

它的目标是作为后续“药膳知识库、检索与校验”的统一结构底座。

## 结构摘要

顶层结构：

- `HerbalMedicineSchema.基础属性`
- `HerbalMedicineSchema.中医药性`
- `HerbalMedicineSchema.功效主治`
- `HerbalMedicineSchema.药膳应用`
- `HerbalMedicineSchema.现代研究`
- `HerbalMedicineSchema.古籍溯源`

当前文件采用“Schema 模板”方式：以示例值（如 `"string"`、枚举集合）表达字段含义与约束方向，便于团队统一录入口径。

## 字段设计原则

- **主键稳定**：优先用“药材名 + 拉丁学名”形成稳定识别。
- **语义分层**：药性、功效、药膳应用、现代研究分层维护，避免一字段多语义。
- **枚举先行**：对高频分类字段（四气、五味、归经、体质等）优先枚举化，降低歧义。
- **古今并重**：同一药材可并行维护“古籍依据 + 现代研究”，支持临床与科研双视角。

## 与现有模块的关系

当前阶段该文件为“知识框架配置”，尚未接入现有菜谱 CRUD 校验主链路。  
建议后续按以下节奏接入：

1. 增加药材实体数据文件（例如 `Data/HerbalMaterials.json`）
2. 新增查询命令（例如 `Get-HerbalMaterial`）
3. 在药膳菜谱场景引入可选字段（如 `HerbalMaterials`）
4. 按需扩展验证函数，做基础字段与禁忌检查

## 风险与合规提示

- 本框架用于知识管理与结构化整理，不替代医生诊断与个体化处方。
- 涉及毒性、禁忌、特殊人群时，录入与发布前应进行人工复核。
- 现代研究字段应尽量标注来源，避免“结论化但无证据链”。

## 维护建议

- 先固化字段，再逐批录入代表性药材，避免一开始过度铺量。
- 每次扩展字段时同步更新本说明文档，保持结构与解释一致。
- 若后续需要高强度检索，建议将部分自由文本升级为对象结构（含来源、证据等级、更新时间）。
