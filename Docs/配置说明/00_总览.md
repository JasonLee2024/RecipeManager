# 配置说明总览

本项目将多维“词库/枚举/索引”拆分为多个独立 JSON 文件，以降低耦合、提高内聚，并支持按维度持续扩展。

## 配置文件一览（位于 `Config/`）

- `Settings.json`
  - **用途**：模块启动的“总配置入口”，包含策略、存储路径、以及各维度 JSON 的路径引用。
  - **特点**：不承载枚举大表，只做“路径编排 + 策略开关”。

- `RecipeTaxonomy.json`（原 `Enums.json`）
  - **用途**：菜谱“分类/标签体系”的核心枚举（如 `Categories`、`TagTaxonomy`、以及分类层级 `CategoryHierarchy`）。

- `RegionalCuisines.json`
  - **用途**：地域/菜系名称词库（独立维度）。

- `CookingTechniques.json`
  - **用途**：烹饪技法词库（按介质、火候、预处理聚类），并提供别名归一映射（Aliases）。

- `Noodles.json`
  - **用途**：面食条目库（用于 `NoodleStyle` 等可选字段校验/检索）。

- `Beverages.json`
  - **用途**：饮料总类目（大类框架），并通过路径引用外部茶体系（中国茶）。

- `ChineseTea.json`
  - **用途**：中国茶体系与凉茶草本体系（独立文件，供 `Beverages.json` 的 Tea 分支引用）。
- `PreparationByIngredientState.json`
  - **用途**：按食材状态聚类的“备料预处理决策表”，并配套工作流时间线（用于备料阶段标准化）。
- `HerbalMedicineSchema.json`
  - **用途**：中医药膳药材知识框架（药性、功效、配伍禁忌、现代研究、古籍溯源等维度）。

## 与数据/文档的关系

- `Data/Recipes/`（`Settings.json` 中 `Storage.RecipeRoot`）
  - **分片存储**：每条菜谱一个 JSON 文件，路径为 `Data/Recipes/{一级 Category}/{安全菜名}.json`；仅扫描该目录树，不会误扫 `Data/` 下其它数据文件。
  - **迁移入口**：历史单体文件路径仍由 `Storage.RecipePath`（如 `Data/Recipes.json`）指定；若分片目录下尚无 `.json` 文件且该单体文件存在，则 `Get-Recipe` / `Invoke-DataProvider -Load` 仍从单体文件读取。迁移请使用 `Migrate-RecipeStorage` 或 `Tools/Migrate-RecipesToShardStorage.ps1`，迁移后原文件会归档为 `*.legacy.bak`。
  - **可选字段**：`DocPath` / `DocCategories` 用于与文档归档建立映射（若启用索引校验）。

- `Docs/CategoryDocIndex.json`
  - **用途**：实现“分类 ↔ 文档路径”的双向映射索引，便于校验、检索与归档一致性维护。

## 约束与约定（建议作为团队共识）

- **JSON 文件不写注释**：所有说明统一放在 `Docs/配置说明/` 下。
- **维度独立**：分类（Enums）、地域（RegionalCuisines）、技法（CookingTechniques）、饮料（Beverages/ChineseTea）、面食（Noodles）等互不混用，避免“一个字段承载多个语义”。
- **可选字段优先**：在菜谱 JSON（分片或历史单体）中新增业务维度时，优先以可选字段方式扩展（如 `NoodleStyle`、`Techniques`、`DocPath` 等），而不是滥用 `Tags` 变成“万能字段”。
