# RegionalCuisines 维护与扩展速查

对应配置文件：`Config/RegionalCuisines.json`

本文是 `05_RegionalCuisines_地域菜系.md` 的操作补充，聚焦“地域菜系标签如何稳定维护”。

---

## 1. 适用场景

- 新增地域菜系条目
- 在“八大菜系/其他地方菜系”之间调整归属
- 排查 `RegionalCuisine`（或相关字段）检索/校验异常

---

## 2. 结构约定（当前版本）

`Config/RegionalCuisines.json` 当前为双分组结构：

- `八大菜系`
- `其他地方菜系`

约定：

- 条目粒度保持“菜系/地域饮食流派名”，不要混入具体菜名
- 尽量避免同一条目多处重复
- 命名以团队约定为准（如“沪菜/本帮菜”这种复合写法可保留）

---

## 3. 维护 SOP（推荐）

1. 明确新增条目的归属层级（八大菜系 or 其他地方菜系）
2. 检查是否已存在同名或近义条目
3. 新增/迁移条目后保证 JSON 结构合法
4. 执行测试，确认模块加载与校验逻辑正常
5. 若涉及命名规范调整，同步更新 `05_RegionalCuisines_地域菜系.md`

---

## 4. 常见问题排查

### Q1：同一地区出现多个近义写法

处理建议：

- 先确定“标准写法”保留在主列表
- 近义写法不要重复塞进主列表，可在后续版本考虑别名映射结构

### Q2：条目该放“八大菜系”还是“其他地方菜系”

当前建议：

- 以现有分组语义和团队共识为准
- 有争议条目先记录到文档说明，再决定是否重构层级

---

## 5. 扩展建议（未来版本）

如需更强表达能力，可升级为对象结构，例如：

```json
{
  "Name": "潮汕菜",
  "Group": "其他地方菜系",
  "Aliases": [],
  "Region": "广东",
  "Notes": ""
}
```

升级前建议确认：

- 校验逻辑是否同步适配
- 既有数据是否迁移
- 是否需要引入“别名归一”策略文件
